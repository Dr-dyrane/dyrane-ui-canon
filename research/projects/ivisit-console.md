## Provisional role in the canon

iVisit Console is currently the strongest evidence for the moment Dyrane UI changed from founder-enforced visual preference into an estate-wide doctrine with migration gates, donor patterns, page admission, parity audits and explicit supersession of older design documents.

My Finance is more semantically refined. iVisit Console is more important historically as the bridge.

## Verified design pivot

The repository records a concentrated transformation between July 6 and July 10, 2026.

### Removed or reduced

- premium-glass defaults;
- indiscriminate backdrop blur;
- heavy shadows and glows;
- brand red used for neutral emphasis;
- shadcn Card/Table/Badge chrome on data surfaces;
- borders and hairlines as universal row separators;
- arbitrary radius values;
- bespoke mobile page grammars;
- status-only right blades and duplicated color systems;
- fake or degenerate visual metrics;
- skeletons painted over complete warm-cache data;
- UI commands without proven backend receivers.

### Introduced or strengthened

- borderless CSS-grid rows;
- canonical squircle radius roles;
- literal semantic status palettes;
- per-hue active states;
- shared mobile LIST grammar;
- date and data-driven grouping;
- identity islands;
- status/vital tracks;
- honest empty-state cause priority;
- skeleton-for-assembly versus Updating-for-refetch;
- fail-closed actions;
- feature-parity audits against baseline;
- role/persona matrices;
- design hardgates and grammar harnesses;
- live computed-style verification.

## Important findings

### 1. Borderless is corrective, not ornamental

The migration repeatedly replaces tables, cards and badges because their inherited borders created parallel grouping and made pages feel like separate templates. Borderlessness is used to let spacing, tone, identity and column rhythm carry hierarchy.

This does not prove every divider is forbidden. It proves default framework chrome must justify itself.

### 2. Brand color loses universal authority

The console’s primary red was producing false alarm and false selection meaning. Neutral actions and active filters moved to foreground or their own semantic hue. Destructive red remained.

This is an early verified form of the later Dyrane rule that color must declare its responsibility.

### 3. Truth outranks visual completeness

Multiple commits preserve fail-closed commands, blocked write paths and visual-only admissions. The console distinguishes a surface that looks complete from a receiver that has authority to perform the action.

This is a major product-intelligence and trust contribution.

### 4. Grammar is data-aware

Adaptive grouping measures whether a candidate factor produces useful groups. Degenerate singletons or one giant bucket cause a fallback to another meaningful grouping factor.

This is stronger than a fixed style rule: the grammar adapts to the data distribution while preserving understandable limits.

### 5. Static tests do not prove rendering

A Tailwind opacity defect showed that source-level classes could pass every design gate while compiling to no visible tint. The fix added token hygiene and established computed-style verification as a separate requirement.

This should become a canon compliance principle:

> Source compliance and rendered compliance are separate evidence classes.

## Anti-canon evidence

The repository also preserves examples of what Dyrane UI moved away from:

- decorative glass everywhere;
- red as universal active color;
- generic card/table/badge composition;
- uppercase and tracking as indiscriminate hierarchy;
- fixed grouping factors that ignore data shape;
- visual affordances for unauthorized actions;
- static gates treated as proof of actual rendering.
