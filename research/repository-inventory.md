Status: normalized candidate set for PASS-001

Authority: research, not canon

## Purpose

This inventory separates portfolio evidence from noise before scoring. Inclusion means a repository may contain authored product or interface evidence. It does not mean the repository is mature, original in every part, or canon-worthy.

## Classification

- **A — Reference candidate:** mature product with strong authored UI and enough evidence for deep audit.
- **B — Comparative product:** meaningful product UI that can validate, contradict, or date a pattern.
- **C — Evolutionary evidence:** smaller or older interface useful for tracing design development.
- **D — Context only:** weak, incomplete, template-heavy, or narrow evidence; inspect selectively.

Audit depth:

- **Deep:** source structure, primitives, states, responsive behavior, motion, and representative surfaces.
- **Focused:** inspect the strongest relevant subsystem.
- **Triage:** establish provenance, maturity, and whether deeper work is justified.

## Normalization rules

1. A repository can contribute evidence without receiving a numeric score.
2. Repository size is not a proxy for design maturity.
3. Private/public status does not affect design weight.
4. A related product split across repositories is audited both separately and as one lineage.
5. Framework defaults, tutorials and generated starter code are excluded from authored-pattern claims.
6. Documentation may explain intent but does not prove shipped behavior without implementation evidence.
7. Recent products receive no automatic authority; repeated and enforceable decisions receive more weight.
